## 项目简介

综测（综合素质测评）每学年评一次，流程是固定的：翻出一年的证书和聘书，对照学院评分细则一条条找加分项，算分，再把材料按「德智体美劳」五个文件夹重命名排好，最后填一张评定表交给班委。

真正耗时的不是算分，是**把照片上的信息抄进表格**和**按规格重命名归档**。这两个活重复、易错，且没有任何判断成分，正适合交给工具。

本项目是一个 Windows 本地单机程序：双击 exe，浏览器打开一个页面，拖进证书照片，识别、算分、打包一次完成。**材料不离开本机**，只有证书图片会发往你自己配置的视觉模型。

> 适用范围：内置广东金融学院 · 计算机学院 2026 版细则。换学院、或学院换了新一年的细则，在页面「③ 评分规则」里传一份新 PDF 即可，不用改代码（见[配置说明](#配置说明)）。

## 功能特性

| 模块 | 功能 | 说明 |
|------|------|------|
| ① 本人信息 | 姓名 / 学号 / 班级 / 学院 / 年级 | 填一次，所有材料统一采用。姓名不交给模型去认，避免"廖展滨"被读成"廖展斌" |
| ② 模型配置 | 多套配置并存与切换 | 自己的 API Key（BYOK），DPAPI 加密存本机，保存前先测连通性，测不通自动回滚 |
| ③ 评分规则 | 上传细则自动转 YAML | 换学院、换年份时传一份新细则，逐页读表后生成规则草稿，人工核对分值再保存生效；旧配置自动备份成 `.bak` |
| ④ 材料识别 | 图片 / PDF / Word 批量上传 | 统一转成逐页图片送视觉模型，抽出 13 个字段：类型、姓名、单位、日期、名称、等级、级别、类别等 |
| ⑤ 待确认 | 歧义字段集中处理 | 模型不确定、姓名对不上、没读到的字段自动汇总成清单，改完即最终结果 |
| ⑥ 算分 | 五育规则引擎 | 22 个规则组、85 条细则；学年窗口校验、多候选选择、手动排除与强制计入 |
| ⑦ 导出 | 按学院规格打包 | 德/智/美/体/劳 五个文件夹（编号各自从材料1开始）+ 综测评定表 xlsx（总表 + 加分明细两个 sheet） |

几个刻意的设计取舍：

- **AI 不负责算分。** 识别只回答"证书上写了什么"，分值完全由本地规则引擎按 YAML 计算。同样的输入永远同样的结果，能追到具体条款。
- **规则导入不是"上传即生效"。** 加分表是「级别 × 等次」的二维表，读错一格会给整班算错分，而这个错误当场看不出来。所以分两步：先出草稿铺开核对，确认后才覆盖配置。
- **不替你下判断。** 超出学年窗口但学院认可的奖项、细则里没有对应条目的材料，工具只提示不处理，由你和班委决定。
- **分数是草稿。** 导出的评定表明确可复核，最终分值以班委审核为准。

## 快速开始

### 环境要求

| 项目 | 要求 |
|------|------|
| 系统 | Windows 10 / 11（x64） |
| 运行打包版 | 无需安装任何东西，不依赖本机 Java |
| 从源码运行 | JDK 21+、Maven 3.9+ |
| 识别 Word 材料 | 本机需装 LibreOffice（可选，不装则只支持图片和 PDF） |
| 视觉模型 | 任选一家支持图片输入的模型，需自备 API Key |

### 使用打包版（推荐）

1. 解压 `综测整理-0.1.0.zip`
2. 双击 `综测整理/综测整理.exe`
3. 浏览器自动打开 `http://127.0.0.1:18080`
4. 关闭页面即自动退出，不留后台进程

配置（`configs/`）和 Key 都在 exe 外面，改规则不需要重新打包。

### 从源码运行

```bash
cd file-integration

# 本机 Maven 环境正常时
mvn spring-boot:run

# 或先打包再运行（单进程，方便 kill）
mvn package -DskipTests
java -jar target/assessment-0.1.0-SNAPSHOT.jar --server.port=18080
```

### 打包成 exe

```bash
cd file-integration
bash build-app.sh
```

产物在 `dist/综测整理/`，用 `app-image` 模式（不需要 WiX），整个目录压缩后发给别人，对方解压双击即可运行。

## 使用流程

```
① 填本人信息  →  ② 配模型 Key  →  ③ 导入评分细则  →  ④ 拖入材料  →  ⑤ 处理待确认  →  ⑥ 算分  →  ⑦ 导出 zip
   仅首次         仅首次            每学年一次（换细则时）   每学年一次       改几处字段        手填基础分      交给班委
```

1. **我的信息**：姓名必填，它是判断"这份材料是不是你的"的唯一依据。
2. **模型配置**：选厂商会自动带出接口地址和模型名，可以改；保存时立刻测一次。
3. **评分规则**：传一份学院的评分细则（PDF / Word / 图片），逐页读表后列出识别到的全部条目。黄色行是没读到分值的，直接补数字或删掉；标题重复、分值不对的当场改。核对完填学院名，点保存才真正覆盖配置，旧文件自动备份。
4. **上传材料**：一次可选多份，同时识别 3 份，单份约 4–9 秒。扫完自动展开有问题的条目。
5. **待确认**：模型不确定或没读到的字段集中在这里改，改完自动标记已确认。
6. **算分**：选评测学年，手填证书上没有的基础分（学年总结自评、互评分等），点开始算分。每条加分都能看到依据条款；有多个可能等级时可以换候选，勾掉则不计入。
7. **导出**：先预览打包结构，确认无误再导出。zip 按「学号_姓名」命名，同时在本机另存一份。

## Token 消耗与费用
> 目前仅测试了 DeepSeek V4.1 flash 模型，其他有待补充

只有 ③ 评分规则导入 和 ④ 材料识别 会产生 API 调用；**算分、生成 Excel、打包 zip 全部在本地完成，消耗 0 token**。

### 先说结论：一轮优化，耗时降到 1/4、token 降到 1/3

2026-10-29 针对"太慢、太贵"做了一轮优化（关闭思考模式 + 图片压缩 + 并发 + 渲染前收手）。同一个模型、同一批材料的前后对比：

| 场景 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 单份材料（1 页） | 29 s / 5,942 tok | **6.6 s / 2,057 tok** | 快 4.4 倍 · 省 65% token |
| 6 份材料整批 | 136 s | **18 s** | 快 7.6 倍 |
| 5 页扫描 PDF | 26 s | **10.3 s** | 快 2.5 倍 |
| 37 页细则导入 | — | **70 s / 8 万 tok** | 新增功能 · 每学年只跑一次 |

省下来的主要不是图片，而是**思考文本**：同一张证书开思考要 5,942 token，关掉只要 2,057——识别是"看字抄字"，不需要推理，而思考模式会把输出预算吃满，正文还没写完就被截断，触发翻倍重试，等于每份多付一次完整调用。关掉之后准确率没有下降（金标准三张样例全对）。

### 优化后的实测明细

模型 `deepseek-flash`，2026-10 实测（关键设置：关闭思考模式、图片长边压到 1600 / JPEG q88、逐页并发 3）：

| 场景 | 页数 | Token | 耗时 |
|------|------|-------|------|
| 单份材料（聘书 / 证书照片） | 1 | ≈ 2,057 | 4–8 s |
| 5 页扫描 PDF（整份材料） | 5 | ≈ 10,300 | 10.3 s |
| 一份 37 页的学院评分细则 | 37 | ≈ 80,000 | 70 s |

单份材料的 token 几乎是常数：图片本身只占约 250 token，剩下约 1,800 是 prompt 和字段输出。所以**份数比页数更能决定成本**。

优化项一共四处，都是可复现的设置，不是运气：

| # | 优化 | 效果 |
|---|------|------|
| 1 | 关闭思考模式（`thinking: disabled`） | 单份 29 s → 6.6 s，5,942 → 2,057 tok |
| 2 | 图片长边压到 1600 / JPEG q88 | 图片 token 稳在 250 左右，且不影响字段准确率 |
| 3 | 前端并发 3 份 + 后端逐页虚拟线程 | 6 份整批 136 s → 18 s |
| 4 | PDF 渲染阶段就按页数上限收手 | 5 页 PDF 26 s → 10.3 s（不再"全渲染再截断"） |

> 端点不支持 `thinking` 参数时（非 DeepSeek 或老网关）会自动摘掉重发一次，不影响结果。

### 一次完整流程的估算

按典型情况 **10 份材料**（一学年五育各类奖项的常见数量）估算：

| 项目 | 数值 |
|------|------|
| 调用次数 | 10 次（每份 1 页） |
| 总 Token | ≈ 20,600（输入 ≈ 18,800 + 输出 ≈ 1,800） |
| 费用（高峰时段） | **约 $0.008 ≈ ¥0.06** |
| 费用（低谷时段） | 约 $0.004 ≈ ¥0.03 |
| 加上每学年一次的细则导入 | 再 ≈ ¥0.21（37 页，仅换细则那年需要） |

规模参考：

| 材料份数 | Token | 费用（高峰） |
|---------|-------|-------------|
| 5 份 | ≈ 10,300 | ≈ ¥0.03 |
| 10 份 | ≈ 20,600 | ≈ ¥0.06 |
| 20 份 | ≈ 41,000 | ≈ ¥0.12 |

### 计价口径

`deepseek-flash` 官方价格（2026-10，美元 / 百万 token）：

| 项目 | 高峰 | 低谷 |
|------|------|------|
| 输入（缓存未命中） | $0.30 | $0.15 |
| 输出 | $1.20 | $0.60 |

- 图片按尺寸折算成输入 token 计费。
- 低谷时段为高峰的 50%，即 UTC 01:00–04:00 与 06:00–10:00 之外（含周末）。
- 上述按「输入 1,880 / 输出 180」每份估算，汇率为 1 USD ≈ 7.1 CNY。实际以账单为准。
- 价格随官方调整，请以 [DeepSeek 定价页](https://api-docs.deepseek.com/quick_start/pricing) 为准。

### 什么情况会多花钱

- **重扫**：同一份材料重新识别会重新计费。改姓名不需要重扫，工具会直接回刷已识别结果。
- **多页 PDF**：每页一次调用。单份最多读前 5 页，第 6 页起**不会渲染也不会计费**，但也不会被识别——需要你自己处理。
- **重新导入细则**：整份细则每页都要读，这是一次性成本。同一份细则不用反复导入，倒回去改分值可以在页面上直接改后保存，不重新调模型。
- **识别失败重试**：模型输出被截断时工具会自动放大预算重试一次。

换用其他厂商的模型，Token 量级接近，单价不同，按上表换算即可。

## 配置说明

### 模型配置

在页面「② 模型配置」里填写，无需改文件。Key 用 Windows DPAPI 加密后存于：

```
%LOCALAPPDATA%\Assessment\llm.json
```

只有当前 Windows 用户能解开。可以存多套配置随时切换，适合"平时用便宜模型、重要材料换强模型"的用法。

模型名不写死——任何支持图片输入的模型填进去都能用（选厂商只是预填地址，可改）。

### 规则配置

规则 YAML 是算分的唯一依据，放在包外，改完重启即生效，不必重新打包。

```
configs/
├── gduf/计算机学院.yaml     五育评分细则（22 组 / 85 条）
├── _school/广东金融学院.yaml 校发办法里的公共部分
└── prompt/
    ├── extract-v2.txt       材料识别的 prompt
    └── rules-v1.txt         细则表格转规则的 prompt
```

**换学院 / 换年份优先用页面导入**（③ 评分规则）：传一份新细则，工具读完后把全部条目铺开给你核对，确认后覆盖 `configs/gduf/计算机学院.yaml`，旧文件留在同目录的 `.bak-时间戳`。

导入只替换 `rule_groups`，`formulas` / `dimensions` / `global_constraints` 原样保留——这些是学校统一规定的算法和打包规格，不在学院细则里，重新生成会丢。

也可以直接手写 YAML。顶层四段：

```yaml
meta:                     # 学校 / 学院 / 版本 / 来源文件
  school: 广东金融学院
  college: 计算机学院
formulas:
  overall: "德育*0.20 + 智育*0.60 + 体育*0.10 + 美育*0.05 + 劳育*0.05"
dimensions:               # 五育权重、公式、需要手填的基础分
  - id: moral
    name: 德育
    weight: 0.20
    formula: "base*0.30 + peer*0.20 + bonus*0.50 - deduction"
    inputs:
      - { key: base, name: 德育基础分 }
      - { key: peer, name: 互评分 }
global_constraints:
  time_window: true
rule_groups:              # 加分 / 扣分条目
  - id: moral_1
    dimension: moral
    kind: bonus
    name: 学生干部
    note: 身兼多项只取最高
    items:
      - match: { level: 校级, titles: [部长, 主席] }
        score: 6
        note: 任满一学年
      - match: { level: 校级, titles: [学术论文] }
        score: 3
        manual: true      # 分值与作者位次相关，故意不自动算分
```

`match` 常用键：`doc_type` / `level` / `titles` / `achievement` / `issuer`，后三个是「任一关键词作为子串出现」即命中。

标了 `manual: true` 的条目不会自动给分，页面上显示成「需人工」，由人看着折算表填——典型的是学术论文和报告文章，分值和作者位次绑定，读不准位次就宁可不算。

## 已知限制

- **细则导入必须人工核对**：转换是概率性的，二维表里读错一格就会给整班算错分。工具把缺分值、条件相同但分值不同的条目（多半是表里还有一列角色没区分）标出来，但不保证一次读全——漏掉的组和条目要自己补。
- **只对一座学校的算法做过验证**：五育公式和打包规格按 GDUF 2026 版实现，换学校要连 `formulas` / `dimensions` 一起改。
- **结果必须复核**：识别是概率性的，姓名、等级、日期都可能读错。工具用「待确认清单」把这些暴露出来，但不保证零错误。
- **多人材料**：一张证书上有多个姓名时，只提示"含他人姓名"，不会自动框出哪个是你（二期）。
- **Word 材料**：依赖本机 LibreOffice 转换，没装则只能上传图片和 PDF。
- **单份 ≤ 20 MB**，超过的不做自动识别（请拆页或压缩后重传，材料本身可以留着，导出后手工归档）。
- **PDF 单份最多读前 5 页**，第 6 页起需自己处理——这个上限是为了不让一份几十页的扫描件烧掉整月额度。
- **仅 Windows**：打包用 jpackage app-image，未做 macOS / Linux 分发。
