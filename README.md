## 项目简介

综测（综合素质测评）每学年评一次，流程是固定的：翻出一年的证书和聘书，对照学院评分细则一条条找加分项，算分，再把材料按「德智体美劳」五个文件夹重命名排好，最后填一张评定表交给班委。

真正耗时的不是算分，是**把照片上的信息抄进表格**和**按规格重命名归档**。这两个活重复、易错，且没有任何判断成分，正适合交给工具。

本项目是一个 Windows 本地单机程序：双击 exe，浏览器打开一个页面，拖进证书照片，识别、算分、打包一次完成。**材料不离开本机**，只有证书图片会发往你自己配置的视觉模型。

> 适用范围：广东金融学院 · 计算机学院 · 2026 版评分细则。其他学院需要自己写一份规则 YAML（见[配置说明](#配置说明)）。

## 功能特性

| 模块 | 功能 | 说明 |
|------|------|------|
| ① 本人信息 | 姓名 / 学号 / 班级 / 学院 / 年级 | 填一次，所有材料统一采用。姓名不交给模型去认，避免"廖展滨"被读成"廖展斌" |
| ② 模型配置 | 多套配置并存与切换 | 自己的 API Key（BYOK），DPAPI 加密存本机，保存前先测连通性，测不通自动回滚 |
| ③ 材料识别 | 图片 / PDF / Word 批量上传 | 统一转成逐页图片送视觉模型，抽出 13 个字段：类型、姓名、单位、日期、名称、等级、级别、类别等 |
| ④ 待确认 | 歧义字段集中处理 | 模型不确定、姓名对不上、没读到的字段自动汇总成清单，改完即最终结果 |
| ⑤ 算分 | 五育规则引擎 | 22 个规则组、85 条细则；学年窗口校验、多候选选择、手动排除与强制计入 |
| ⑥ 导出 | 按学院规格打包 | 德/智/美/体/劳 五个文件夹（编号各自从材料1开始）+ 综测评定表 xlsx（总表 + 加分明细两个 sheet） |

几个刻意的设计取舍：

- **AI 不负责算分。** 识别只回答"证书上写了什么"，分值完全由本地规则引擎按 YAML 计算。同样的输入永远同样的结果，能追到具体条款。
- **不替你下判断。** 超出学年窗口但学院认可的奖项、细则里没有对应条目的材料，工具只提示不处理，由你和班委决定。
- **分数是草稿。** 导出的评定表明确可复核，最终分值以班委审核为准。

## 快速开始

### 环境要求

| 项目 | 要求 |
|------|------|
| 系统 | Windows 10 / 11（x64） |
| 运行打包版 | 无需安装任何东西，不依赖本机 Java |
| 从源码运行 | JDK 21+、Maven 3.9+ |
| 识别 Word 材料 | 本机需装 LibreOffice（可选，不装则只支持图片和 PDF） |
| 视觉模型 | 任选一家支持图片输入的模型，需自备 API Key |

### 使用打包版（推荐）

1. 解压 `综测整理-0.1.0.zip`
2. 双击 `综测整理/综测整理.exe`
3. 浏览器自动打开 `http://127.0.0.1:18080`
4. 关闭页面即自动退出，不留后台进程

配置（`configs/`）和 Key 都在 exe 外面，改规则不需要重新打包。

### 从源码运行

```bash
cd file-integration

# 本机 Maven 环境正常时
mvn spring-boot:run

# 或先打包再运行（单进程，方便 kill）
mvn package -DskipTests
java -jar target/assessment-0.1.0-SNAPSHOT.jar --server.port=18080
```

### 打包成 exe

```bash
cd file-integration
bash build-app.sh
```

产物在 `dist/综测整理/`，用 `app-image` 模式（不需要 WiX），整个目录压缩后发给别人，对方解压双击即可运行。

## 使用流程

```
① 填本人信息  →  ② 配模型 Key  →  ③ 拖入材料  →  ④ 处理待确认  →  ⑤ 算分  →  ⑥ 导出 zip
   仅首次         仅首次          每学年一次       改几处字段        手填基础分      交给班委
```

1. **我的信息**：姓名必填，它是判断"这份材料是不是你的"的唯一依据。
2. **模型配置**：选厂商会自动带出接口地址和模型名，可以改；保存时立刻测一次。
3. **上传材料**：一次可选多份，逐份识别，单份约 5–30 秒。扫完自动展开有问题的条目。
4. **待确认**：模型不确定或没读到的字段集中在这里改，改完自动标记已确认。
5. **算分**：选评测学年，手填证书上没有的基础分（学年总结自评、互评分等），点开始算分。每条加分都能看到依据条款；有多个可能等级时可以换候选，勾掉则不计入。
6. **导出**：先预览打包结构，确认无误再导出。zip 按「学号_姓名」命名，同时在本机另存一份。

## Token 消耗与费用
> 目前仅测试了Deepseek V4.1flash模型，其他有待补充
只有第 ③ 步「识别」会产生 API 调用，**算分、生成 Excel、打包 zip 全部在本地完成，消耗 0 token**。

### 实测数据

用两份真实材料实测（模型 `deepseek-flash`，2026-10）：

| 材料 | 页数 | 文件大小 | Token | 耗时 |
|------|------|---------|-------|------|
| 聘书照片（手机拍摄，含桌面背景） | 1 | 471 KB | 3,301 | 16.2 s |
| 获奖证书（电子证书导出 PNG） | 1 | 1.4 MB | 5,662 | 29.2 s |
| **单份平均** | 1 | — | **≈ 4,500** | ≈ 23 s |

差异主要来自图片尺寸和模型的思考长度，不来自字段多少。

### 一次完整流程的估算

按典型情况 **10 份材料**（一学年五育各类奖项的常见数量）估算：

| 项目 | 数值 |
|------|------|
| 调用次数 | 10 次（每份 1 页） |
| 总 Token | 约 45,000（输入 ≈ 30,000 + 输出 ≈ 15,000） |
| 费用（高峰时段） | **约 $0.027 ≈ ¥0.19** |
| 费用（低谷时段） | 约 $0.0135 ≈ ¥0.10 |

规模参考：

| 材料份数 | Token | 费用（高峰） |
|---------|-------|-------------|
| 5 份 | ≈ 22,500 | ≈ ¥0.10 |
| 10 份 | ≈ 45,000 | ≈ ¥0.19 |
| 20 份 | ≈ 90,000 | ≈ ¥0.38 |

### 计价口径

`deepseek-flash` 官方价格（2026-10，美元 / 百万 token）：

| 项目 | 高峰 | 低谷 |
|------|------|------|
| 输入（缓存未命中） | $0.30 | $0.15 |
| 输出 | $1.20 | $0.60 |

- 图片按尺寸折算成输入 token 计费。
- 低谷时段为高峰的 50%，即 UTC 01:00–04:00 与 06:00–10:00 之外（含周末）。
- 上述拆分按「输入 3,000 / 输出 1,500」估算，汇率为 1 USD ≈ 7.1 CNY。实际以账单为准。
- 价格随官方调整，请以 [DeepSeek 定价页](https://api-docs.deepseek.com/quick_start/pricing) 为准。

### 什么情况会多花钱

- **重扫**：同一份材料重新识别会重新计费。改姓名不需要重扫，工具会直接回刷已识别结果。
- **多页 PDF**：每页一次调用。单份最多读前 5 页，第 6 页起**不会渲染也不会计费**，但也不会被识别——需要你自己处理。
- **识别失败重试**：模型输出被截断时工具会自动放大预算重试一次。

换用其他厂商的模型，Token 量级接近，单价不同，按上表换算即可。

## 配置说明

### 模型配置

在页面「② 模型配置」里填写，无需改文件。Key 用 Windows DPAPI 加密后存于：

```
%LOCALAPPDATA%\Assessment\llm.json
```

只有当前 Windows 用户能解开。可以存多套配置随时切换，适合"平时用便宜模型、重要材料换强模型"的用法。

模型名不写死——任何支持图片输入的模型填进去都能用（选厂商只是预填地址，可改）。

### 规则配置

```
configs/
├── _school/           学校级公共规则
├── prompt/            识别用的 prompt 模板
└── 广东金融学院/
    └── 计算机学院.yaml  五育评分细则（22 组 / 85 条）
```

规则 YAML 是算分的唯一依据，改完重启即生效，不必重新打包。结构：

```yaml
dimensions:
  - id: moral
    name: 德育
    weight: 0.20
    inputs:                    # 证书上没有、必须手填的分
      - key: moral.base
        name: 德育基础分
    groups:
      - id: student-cadre
        name: 学生干部
        match: { titles: [干事, 部长, 主席] }
        score: 5
```

其他学院复用时，复制一份 YAML 改数值即可，不需要动代码。标了 `manual: true` 的条目（如学术论文，分值与作者位次相关）故意不自动算分，由人看着折算表填。

## 已知限制

- **单学院细则**：只内置了GDUF 计院 2026 版。其他学院需要自己写 YAML。
- **结果必须复核**：识别是概率性的，姓名、等级、日期都可能读错。工具用「待确认清单」把这些暴露出来，但不保证零错误。
- **多人材料**：一张证书上有多个姓名时，只提示"含他人姓名"，不会自动框出哪个是你（二期）。
- **Word 材料**：依赖本机 LibreOffice 转换，没装则只能上传图片和 PDF。
- **单份 ≤ 20 MB**，超过的不做自动识别（请拆页或压缩后重传，材料本身可以留着，导出后手工归档）。
- **PDF 单份最多读前 5 页**，第 6 页起需自己处理——这个上限是为了不让一份几十页的扫描件烧掉整月额度。
- **仅 Windows**：打包用 jpackage app-image，未做 macOS / Linux 分发。
